# 요구사항 명세서 (SRS) — AutoFit v2 WebAR

> **문서 버전**: 1.1
> **최종 갱신**: 2026-03-03
> **대상 시스템**: WebAR 기반 가상 의류 시착 웹 애플리케이션

---

## 1. 시스템 개요

### 1.1 목적

AutoFit v2는 웹 브라우저에서 실시간 바디 트래킹과 3D 의류 렌더링을 통해
사용자가 온라인으로 의류를 가상 시착할 수 있는 WebAR 애플리케이션이다.

### 1.2 타겟 사용자

| 사용자 유형 | 설명 |
|------------|------|
| 일반 소비자 | 온라인 의류 쇼핑몰에서 구매 전 가상 시착 |
| 업체 담당자 (vendor) | 상품 등록, 이미지 업로드, 사이즈 치수 입력, 3D 에셋 관리 |
| 운영자 (manager) | 의류 카탈로그 운영, 에셋/세션 통계 조회, 모니터링 |
| 시스템 관리자 (admin) | 사용자/권한/RBAC, 브랜드, SDK 설정 등 시스템 전체 관리 |

### 1.3 시스템 범위

- **포함**: 실시간 바디 트래킹, 3D 의류 시착, 의류 카탈로그, 에셋 관리, 사용자 관리, 관리 대시보드
- **미포함**: 결제 시스템, 재고 관리, 배송 추적 (외부 쇼핑몰 시스템 연동)

### 1.4 연동 대상

- 온라인 의류 쇼핑몰 (REST API 연동)
- 3D 에셋 제작 도구 (Blender, CLO3D 등에서 glTF 내보내기)

## 2. 기능 요구사항 (Functional Requirements)

### FR-001: 실시간 바디 트래킹

| 항목 | 내용 |
|------|------|
| **ID** | FR-001 |
| **우선순위** | 필수 (P0) |
| **설명** | 웹캠을 통해 사용자의 전신을 실시간으로 감지하고 추적한다 |

**세부 요구사항**:

| ID | 요구사항 | 수용 기준 |
|----|---------|----------|
| FR-001-01 | 웹캠 접근 권한을 요청하고 카메라 피드를 획득한다 | Camera API로 비디오 스트림 획득, 권한 거부 시 안내 메시지 표시 |
| FR-001-02 | 사용자 전신에서 33개 키포인트의 3D 좌표를 추출한다 | MediaPipe Pose Landmarker 33 키포인트, x/y/z + visibility + presence |
| FR-001-03 | 월드 좌표(미터 단위)를 함께 제공한다 | MediaPipe world landmarks(힙 중심 원점, 카메라 좌표계) 제공 |
| FR-001-04 | 모바일 환경에서 30fps 이상 트래킹을 유지한다 | Android Chrome 기준 30fps 이상 |
| FR-001-05 | 데스크톱 환경에서 60fps 이상 트래킹을 유지한다 | Chrome/Edge 기준 60fps 이상 |
| FR-001-06 | 트래킹 결과에 스무딩 필터를 적용하여 떨림을 제거한다 | 1-Euro Filter 적응형 스무딩 (속도 기반 컷오프 조절, CHI 2012), 시각적 지터 최소화 |
| FR-001-07 | 키포인트 오클루전 시 visibility 기반으로 처리한다 | visibility < 0.5인 키포인트는 이전 값 유지 또는 보간 |
| FR-001-08 | Depth Anything V2 Metric Depth(선택)로 사용자-카메라 거리를 추정한다 | ONNX Runtime Web 기반, 저주기(예: 1~5Hz) 추론 + 실패 시 자동 비활성화 |
| FR-001-09 | depth(가능 시) + 키포인트를 결합하여 7개 신체 치수(cm)를 계산한다 | 결과는 추정치이며 품질 게이트(신뢰도/가림/거리) 통과 시에만 갱신 |
| FR-001-10 | 사용자 존재를 자동 감지한다 | depth 사용 시 거리(0.5~4m) 기반, 미사용 시 Pose 감지 기반으로 폴백 |

### FR-002: 가상 시착

| FR-002-07 | 핏 타입(슬림핏/레귤러핏/오버핏)을 실시간으로 전환하여 시착한다 | 사용자가 핏 타입 선택 시 해당 핏 메쉬 로드 및 표시 |
| FR-002-08 | 실시간 핏 평가 결과(적합도%, 정확도%, 핏 타입)를 사이드바에 오버레이한다 | 핏 평가 UI가 3D 씬 위에 오버레이, 1초 간격 갱신 |
| FR-002-09 | 백그라운드에서 주기적으로 신체 재측정하여 품질을 점진적으로 향상시킨다 | 최초 측정 후 5초 간격(품질 좋음일 때만) 재측정, 신뢰도(표시용) 상한 99 |

### FR-008: Depth 기반 신체 측정

| 항목 | 내용 |
|------|------|
| **ID** | FR-008 |
| **우선순위** | 선택 (P2) |
| **설명** | Depth Anything V2 Metric Depth(가능 시)를 사용해 신체 측정 정확도를 보강한다. 미지원/불안정 환경에서는 pose 기반/사용자 입력으로 폴백한다 |

> **우선순위 변경**: P1 → P2. Depth Anything V2 ONNX 웹 통합의 기술적 복잡도(100MB 모델,
> WebGPU/WebGL 폴백, focal length 미확보)를 고려하여 MVP 이후로 연기한다.
> 신체 측정은 사용자 입력(user_input) + 포즈 비율 추정(pose_scale)으로 폴백한다.

**세부 요구사항**:

| ID | 요구사항 | 수용 기준 |
|----|---------|----------|
| FR-008-01 | Depth Anything V2 Metric Depth 모델을 ONNX Runtime Web으로 로드하고 추론한다 | 모델 초기화 < 10초. 추론은 저주기(예: 1~5Hz)로 수행하며 실패 시 자동 비활성화 |
| FR-008-02 | depth map에서 사용자-카메라 거리(m)를 추출한다 | 키포인트 위치 depth 샘플링 + 중앙값 기반 거리(추정치) 산출 |
| FR-008-03 | 거리/스케일 팩터 + 키포인트 좌표를 결합하여 신체 치수(cm)를 계산한다 | 핀홀 모델 기반 역투영(가능 시) + 캘리브레이션/폴백 포함 |
| FR-008-04 | 측정 결과에 정확도(%) 및 신뢰도 점수를 부여한다 | depth 안정성 + 키포인트 visibility 기반, 신뢰도(표시용) 상한 99 |
| FR-008-05 | 측정이 불가능한 환경(거리 초과, 조명 부족)에서 사용자에게 안내한다 | "카메라에 가까이 와주세요" 등 상황별 안내 메시지 |

### FR-009: 실시간 핏 평가

| 항목 | 내용 |
|------|------|
| **ID** | FR-009 |
| **우선순위** | 필수 (P0) |
| **설명** | 신체 치수(측정 방식: `depth`/`pose_scale`/`user_input`)와 의류 실측 치수를 실시간으로 비교하여 핏 적합도를 평가한다 |

> **폴백 전략**: FR-009는 신체 치수 입력을 3가지 방식으로 지원하므로 FR-008(Depth 기반 측정, P2)이
> 미구현이어도 독립적으로 동작한다:
> 1. **user_input** (P0): 사용자가 직접 키/몸무게/체형 입력
> 2. **pose_scale** (P0): MediaPipe 키포인트 비율 기반 추정
> 3. **depth** (P2): Depth Anything V2 기반 정밀 측정
>
> MVP에서는 user_input + pose_scale만으로 핏 평가를 제공한다.

**세부 요구사항**:

| ID | 요구사항 | 수용 기준 |
|----|---------|----------|
| FR-009-01 | 신체 치수와 의류 실측 치수의 차이를 기반으로 핏 타입(slim/regular/oversize)을 분류한다 | 여유량 < 3cm → slim, 3~8cm → regular, > 8cm → oversize |
| FR-009-02 | 항목별(어깨/가슴/허리/힙) 적합도(%)를 산출한다 | 각 항목의 여유량이 해당 핏 타입 적정 범위 내 → 100%, 벗어난 정도에 비례하여 감소 |
| FR-009-03 | 종합 적합도(%)와 측정 정확도(%)를 시착 화면에 실시간 표시한다 | 사이드바 오버레이, 1초 간격 갱신, 신뢰도(표시용) 상한 99 |
| FR-009-04 | 핏 평가 상세 결과(항목별 차이cm, 핏 타입별 비교)를 확장 패널로 제공한다 | 확장 패널 클릭 시 상세 표 표시 |
| FR-009-05 | 핏 평가 결과를 서버에 저장하여 이력 조회를 지원한다 | POST /api/v1/fit-evaluations로 저장 |

## 2b. 권한 모델 (RBAC)

역할(`users.role`) 기반 접근 제어를 적용한다.

| 역할 | 설명 |
|------|------|
| user | 일반 사용자(시착/이력/즐겨찾기) |
| vendor | 업체 담당자(자기 브랜드 카탈로그/에셋 관리) |
| manager | 운영자(카탈로그 운영/통계/모니터링) |
| admin | 시스템 관리자(사용자/권한/브랜드/SDK 포함 전체) |

핵심 권한 매트릭스(요약):

| 기능 | user | vendor | manager | admin |
|------|------|--------|---------|------|
| 카탈로그 조회 | O | O | O | O |
| 피팅 세션 생성/조회 | 본인 | 익명/자기브랜드 통계 | 전체(운영 목적) | 전체 |
| 신체 측정/핏 평가 저장 | 본인(옵트인) | - | - | - |
| 즐겨찾기 | 본인 | - | - | - |
| 브랜드 생성/삭제 | - | - | - | O |
| 의류/이미지/변형 CRUD | - | 자기 브랜드 | O | O |
| SDK 설정 관리 | - | 자기 브랜드 | O | O |
| 사용자/권한 관리 | - | - | - | O |

> vendor의 리소스 범위는 `users.brand_id`로 강제하며, 타 브랜드 리소스 접근은 403 처리한다.

## 부록 A: 용어 정의

| 용어 | 정의 |
|------|------|
| WebAR | 웹 브라우저 기반 증강현실. 별도 앱 설치 없이 카메라를 통해 가상 객체를 현실에 오버레이 |
| glTF | GL Transmission Format. 3D 씬/모델 전송을 위한 표준 포맷 |
| GLB | glTF의 바이너리 버전. 모든 데이터를 단일 파일로 패킹 |
| Draco | Google의 3D 메쉬 압축 라이브러리 |
| KTX2 | Khronos Texture Container 2. GPU 압축 텍스처 컨테이너 |
| XPBD | Extended Position-Based Dynamics. 실시간 물리 시뮬레이션 알고리즘 |
| VAT | Vertex Animation Texture. 버텍스 애니메이션을 텍스처로 인코딩하는 기법 |
| SDF | Signed Distance Field. 충돌 감지에 사용되는 거리 필드 |
| EMA | Exponential Moving Average. 지수 이동 평균 스무딩 필터. 본 프로젝트에서는 고정 alpha EMA 대신 1-Euro Filter(속도 적응형 컷오프)를 사용한다 |
| 1-Euro Filter | 입력 신호의 속도에 따라 컷오프 주파수를 적응적으로 조절하는 저역통과 필터. 저속 시 강한 스무딩(지터 제거), 고속 시 약한 스무딩(지연 최소화). Casiez et al., CHI 2012 |
| SkinnedMesh | 본 리깅이 적용된 3D 메쉬. 본 변환에 따라 변형 |
| Depth Anything V2 | 단안 카메라 영상으로부터 depth map을 추정하는 모델. Metric Depth는 절대 스케일을 목표로 하나, 브라우저/디바이스/환경에 따라 보정이 필요할 수 있음 (선택 기능) |
| Metric Depth | 상대 깊이(relative)가 아닌 절대 스케일(미터)을 목표로 하는 depth estimation 방식 |
| Fit Type (핏 타입) | 의류와 신체 간 여유량에 따른 핏 분류. slim(슬림핏), regular(레귤러핏/적정핏), oversize(오버핏) |
| 적합도 (Suitability) | 신체 치수와 의류 치수 간 핏 적합 정도를 백분율(%)로 표현한 값 |
| 정확도 (Accuracy) | 신체 측정 결과의 신뢰도(표시용)를 백분율(%)로 표현한 값. 상한 99 |
