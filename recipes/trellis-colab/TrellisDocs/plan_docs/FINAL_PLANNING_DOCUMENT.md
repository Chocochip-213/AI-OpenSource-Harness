## 1. 프로젝트 개요

### 1.1 목적

본 서비스는 웹 브라우저에서 실시간 바디 트래킹과 3D 의류 렌더링을 통해 사용자가 온라인으로 의류를 가상 시착할 수 있는 WebAR 애플리케이션이다. 별도 앱 설치 없이 모바일/데스크톱 브라우저에서 즉시 의류를 가상 착용할 수 있다.

### 1.2 v1 → v2 전환 배경

v1(매장 미러)은 NVIDIA GPU가 장착된 전용 디바이스를 전제로 설계되었다. TensorRT, CUDA-GL interop, Warp XPBD 등 네이티브 GPU 스택에 의존하여 고성능을 달성했으나, 다음 한계가 명확했다.

| 항목 | v1 매장 미러 | v2 WebAR |
|------|-------------|----------|
| 배포 단위 | 매장별 전용 디바이스 | 브라우저 URL 접속 |
| 하드웨어 의존 | NVIDIA GPU 필수 | GPU 없어도 동작 |
| 사용자 접근성 | 매장 방문 필수 | 온라인 어디서나 |
| 유지보수 | 매장별 원격 관리 | 서버 배포 1회 |
| 확장성 | 디바이스 수 = 매장 수 | 동시 접속 100명+ (목표, 수평 확장 전제) |

**결론**: 온라인 의류 쇼핑몰 연동을 목표로, 브라우저 기반 WebAR로 전환한다.

### 1.3 핵심 목표

- **접근성**: 별도 설치 없이 브라우저에서 즉시 피팅
- **성능**: 모바일 기기에서 30fps 이상 실시간 렌더링
- **에셋 경량화**: Draco + KTX2 압축으로 2MB 이내 에셋
- **프라이버시**: 카메라 영상 서버 전송 금지, 클라이언트 사이드 처리

## 2. 타겟 사용자 및 권한 모델

### 2.1 사용자 유형

| 사용자 유형 | 설명 |
|------------|------|
| 일반 소비자 (user) | 온라인 의류 쇼핑몰에서 구매 전 가상 시착 |
| 업체 담당자 (vendor) | 상품 등록, 이미지 업로드, 사이즈 치수 입력, 3D 에셋 관리 |
| 운영자 (manager) | 의류 카탈로그 운영, 에셋/세션 통계 조회, 모니터링 |
| 시스템 관리자 (admin) | 사용자/권한/RBAC, 브랜드, SDK 설정 등 시스템 전체 관리 |

### 2.2 권한 매트릭스 (RBAC)

역할(`users.role`) 기반 접근 제어를 적용한다.

| 기능 | user | vendor | manager | admin |
|------|------|--------|---------|-------|
| 카탈로그 조회 | O | O | O | O |
| 피팅 세션 생성/조회 | 본인 | 익명/자기브랜드 통계 | 전체(운영 목적) | 전체 |
| 신체 측정/핏 평가 저장 | 본인(옵트인) | - | - | - |
| 즐겨찾기 | 본인 | - | - | - |
| 브랜드 생성/삭제 | - | - | - | O |
| 의류/이미지/변형 CRUD | - | 자기 브랜드 | O | O |
| SDK 설정 관리 | - | 자기 브랜드 | O | O |
| 사용자/권한 관리 | - | - | - | O |

> vendor의 리소스 범위는 `users.brand_id`로 강제하며, 타 브랜드 리소스 접근은 403 처리한다.

## 3. 시스템 범위

### 3.1 포함 범위

- 실시간 바디 트래킹 (웹캠 기반 33개 키포인트 추적)
- 3D 의류 가상 시착 (카메라 피드 위 3D 오버레이)
- 의류 카탈로그 (카테고리별 의류 목록, 검색, 페이지네이션)
- 에셋 관리 (상품 이미지 기반 3D 모델 자동 생성)
- 사용자 관리 (회원가입, 로그인, 역할 기반 권한)
- 관리 대시보드 (카탈로그 CRUD, 통계, 모니터링)
- 핏 기반 사이즈 추천 (신체 치수 vs 의류 치수 비교)
- 실시간 핏 평가 (적합도/정확도 오버레이)

### 3.2 미포함 범위

- 결제 시스템
- 재고 관리
- 배송 추적 (외부 쇼핑몰 시스템 연동)
- SDK 모듈화 및 오프라인 지원 (P3 스코프 아웃)

### 3.3 연동 대상

- 온라인 의류 쇼핑몰 (REST API 연동)
- 3D 에셋 제작 도구 (Blender, CLO3D 등에서 glTF 내보내기)

### 6.2 주요 사용자 시나리오

#### 시나리오 1: 의류 카탈로그 조회 → 가상 시착

```
1. 사용자가 의류 카탈로그를 탐색한다
2. 원하는 의류를 선택한다
3. 카메라 권한을 허용한다 (최초 1회)
4. 시착 화면에서 웹캠 피드 위에 3D 의류가 오버레이된다
5. 사용자 움직임에 따라 의류가 실시간으로 추종한다
6. 사이즈/색상/핏 타입을 변경하며 비교한다
7. 핏 평가 결과(적합도%, 핏 타입)를 확인한다
8. 즐겨찾기에 추가하거나 쇼핑몰 상세 페이지로 이동한다
```

#### 시나리오 2: 업체 상품 등록 → 3D 에셋 생성

```
1. 업체 담당자가 관리 대시보드에 로그인한다
2. 상품 기본 정보(이름, 카테고리, 소재, 핏)를 입력한다
3. 상품 이미지를 업로드한다 (정면/후면/측면/디테일)
4. 사이즈별 실측 치수를 입력한다
5. 3D 모델 자동 생성을 요청한다
6. 생성 상태(pending → processing → ready/failed)를 모니터링한다
7. 완료된 3D 에셋을 미리보기로 확인한다
8. 상품을 게시한다
```

#### 시나리오 3: AR 피팅 세션 (기술 흐름)

```
1. 사용자가 의류를 선택한다 → 피팅 세션 생성
2. GLB 모델 다운로드 ← CDN/Nginx (Draco + KTX2 압축)
3. 카메라 스트림 시작 → MediaPipe Pose (WASM)
4. 포즈 랜드마크 → 본 매핑 → 의류 메쉬 스키닝 + 렌더링 (30fps+)
5. 신체 치수 측정 → 핏 평가 → UI 오버레이 갱신 (1초 간격)
6. 세션 종료 → 소요 시간 기록
```

#### MediaPipe Pose Landmarker 모델 선택

| 모델 | 키포인트 | 정확도 | 속도 (모바일) | 용도 |
|------|---------|--------|-------------|------|
| **Heavy** | 33 | 최고 | 30-40fps | 데스크톱 기본 |
| Full | 33 | 높음 | 40-50fps | 데스크톱/모바일 기본 |
| Lite | 33 | 보통 | 50-60fps | 모바일 폴백 |

- 데스크톱: Heavy (정확도 우선)
- 모바일: Full (성능/배터리 균형)
- 폴백 조건: FPS < 25 지속 3초 → 한 단계 다운그레이드(Heavy→Full→Lite)

```

```

#### 1-Euro Filter 적응형 스무딩

고정 alpha EMA 대비 장점: 입력 신호의 속도(dx/dt)에 따라 컷오프 주파수를 적응적으로 조절하여, **저속 → 강한 스무딩(지터 제거)**, **고속 → 약한 스무딩(지연 최소화)**를 동시에 달성한다.

- **논문**: Casiez, Roussel, Vogel. "1€ Filter" (CHI 2012)
- 33개 키포인트 × 3축(x, y, z) = 99개 필터 인스턴스
- 권장 파라미터: minCutoff=1.0, beta=0.5, dCutoff=1.0

#### 오클루전 처리 전략

- visibility ≥ 0.5: 현재 값 사용 (정상)
- visibility 0.3~0.5: 이전 값과 블렌딩 (부분 오클루전)
- visibility < 0.3: 이전 값 유지 (완전 오클루전)

#### 프레임 버짓 분배

| 단계 | 타겟 시간 | 비고 |
|------|----------|------|
| 카메라 프레임 캡처 | < 1ms | drawImage로 canvas에 복사 |
| MediaPipe 추론 | < 12ms | GPU delegate 사용 시 |
| Depth 추론 (저주기) | 15~50ms | 1~5Hz, rAF 프레임과 분리 |
| 스무딩 필터 | < 0.5ms | 1-Euro Filter |
| 신체 측정 계산 | < 1ms | depth + 키포인트 연산 |
| 핏 평가 계산 | < 0.5ms | 치수 비교 + 핏 분류 |
| Kalidokit 매핑 | < 0.5ms | 벡터/쿼터니언 연산 |
| 본 업데이트 + 렌더 | < 3ms | Three.js 씬 그래프 갱신 |
| **총계 (포즈 루프)** | **< 20ms** | **목표: 50~60fps** |

### 8.2 Kalidokit 포즈→본 매핑

| Neck | 0, 11, 12 | pitch, yaw, roll | 목 회전 |
| Head | 0, 1~10 | pitch, yaw, roll | 머리 회전 |
| LeftUpperArm | 11, 13 | pitch, roll, yaw | 왼쪽 상완 |
| LeftLowerArm | 13, 15 | pitch | 왼쪽 전완 |
| RightUpperArm | 12, 14 | pitch, roll, yaw | 오른쪽 상완 |
| RightLowerArm | 14, 16 | pitch | 오른쪽 전완 |

#### 하반신 본 매핑

| 본 이름 | 입력 키포인트 | 출력 | 설명 |
|---------|-------------|------|------|

| LeftUpperLeg | 23, 25 | pitch, roll | 왼쪽 허벅지 |
| LeftLowerLeg | 25, 27 | pitch | 왼쪽 종아리 |
| RightUpperLeg | 24, 26 | pitch, roll | 오른쪽 허벅지 |

> **호환성 주의**: Kalidokit은 구버전 `@mediapipe/pose` (v1 API) 기준으로 설계되었다. 본 프로젝트의 `@mediapipe/tasks-vision` (v2 API)와 호환을 위해 어댑터 레이어가 필요하다. Kalidokit은 350줄 미만, 의존성 제로이므로 포크하여 v2 포맷에 맞게 수정 가능하다.

### 8.6 에셋 파이프라인

#### 전체 워크플로우

```
업체 상품 등록 (관리 대시보드)
    │ 상품 사진 업로드 (정면/측면/후면/디테일/다각도)
    │ 사이즈별 실측 치수 입력
    │ 핏 타입별 변형 정의 (slim/regular/oversize)
    ↓
Image-to-3D + PBR 추출 (TRELLIS.2, 셀프호스트 GPU)
    │ 상품 사진 → 참조 3D 모델 + 풀 PBR 맵 자동 생성
    │ 출력: GLB (Albedo + Normal + Roughness + Metallic)
    │ [선택] Material Anything으로 PBR 보정
    ↓
Blender 헤드리스 자동화
    │ QuadriFlow 리메쉬 (50k 폴리곤 이하)
    │ Robust Weight Transfer (VRM 바디 프리셋 → 의류 본 웨이트 전사)
    │ 사이즈 검증: 메쉬 치수 vs 입력 치수 ±2cm 이내
    │ 핏 타입 변형 생성: slim/regular/oversize 스케일링
    ↓
gltf-transform (자동화)
    │ Draco 압축 + KTX2 텍스처 + 최적화
    ↓
최종 GLB → CDN 서빙 → 브라우저 로드
```

#### Step 0: 업체 상품 등록

**상품 이미지 업로드:**

| 구분 | 이미지 타입 | 설명 |
|------|-----------|------|
| 필수 | 정면(front) | 최소 1장 |
| 권장 | 정면 + 후면(back) + 측면(side) | 최소 3장 권장 |
| 선택 | 다각도(multi_angle), 플랫레이(flat_lay), 디테일(detail) | 이미지가 많을수록 3D 생성 품질 향상 |

**사이즈별 실측 치수 입력:**

| 카테고리 | 필수 치수 항목 |
|---------|---------------|
| 상의 (top) | 어깨너비, 가슴둘레, 총장, 소매길이 |
| 하의 (bottom) | 허리둘레, 힙둘레, 총장, 인심, 밑위 |
| 원피스 (dress) | 어깨너비, 가슴둘레, 허리둘레, 총장 |
| 아우터 (outer) | 어깨너비, 가슴둘레, 총장, 소매길이 |
| 액세서리 (accessory) | 해당 치수만 |

#### Step 1: Image-to-3D (TRELLIS.2)

| 항목 | 설명 |
|------|------|
| 생성 방식 | Image-to-3D + 풀 PBR (TRELLIS.2 셀프호스트) |
| 입력 | 업체가 업로드한 실제 상품 사진 (앞/뒤/옆) |
| 출력 포맷 | GLB (Albedo + Normal + Roughness + Metallic PBR 맵 포함) |
| GPU 요구 | VRAM 24GB+ (A5000/A6000/H100) |
| 소요 시간 | 3초(512³) ~ 60초(1536³), H100 기준 |
| 상태 추적 | pending → processing → ready / failed |
| 라이선스 | MIT (상업 이용 가능) |

#### Step 2: Blender 헤드리스 자동화

1. **리토폴로지**: QuadriFlow (목표 삼각형: 모바일 3,000~8,000 / 데스크톱 8,000~15,000)
2. **UV 언랩 + 텍스처 베이킹**: 고폴리 → 저폴리 노멀맵 베이킹
3. **자동 리깅**: Robust Weight Transfer (SIGGRAPH Asia 2023)
   - VRM 바디 프리셋 → 의류 본 웨이트 자동 전사
   - 2단계: 고신뢰 전사 → 라플라시안 인페인팅
   - 폴백: Blender Auto Weights → UniRig
4. **사이즈 검증**: 메쉬 바운딩 박스 치수 vs 입력 치수 ±2cm 이내
5. **핏 타입 변형**: MVP에서는 regular만 제작, slim/oversize는 런타임 스케일링

- Draco 메쉬 압축 (크기 80~90% 감소)

- 미사용 데이터 정리, 메쉬 결합

### 8.7 Depth 기반 신체 측정 (P2)

> **스코프 조정**: MVP에서는 P2로 하향하고, 신체 측정은 사용자 직접 입력 또는 포즈 기반 비율 추정(pose_scale)으로 폴백한다.

#### Depth Anything V2 모델 스펙

| 항목 | 값 |
|------|-----|
| 모델 | Depth Anything V2 Metric Depth (Small) |
| 입력 해상도 | 518×518 |
| 출력 | depth map (float32, 미터 단위) |
| 모델 크기 (ONNX) | ~100MB |
| 추론 시간 (데스크톱) | ~15ms (WebGPU) / ~25ms (WebGL) |
| 추론 시간 (모바일) | ~40ms (WebGL) |
| 유효 거리 범위 | 0.5 ~ 4.0m |

#### 운영 정책

- Depth는 **기본 비활성화 또는 저주기(1~5Hz)** 로만 실행
- Pose 30Hz/Render 60Hz와 시간적으로 분리
- 초기화 실패/메모리 압박/저사양/열화 감지 시 자동 비활성화 + 폴백
- UI에는 "정확도" 대신 **신뢰도(표시용) + 품질 상태(좋음/보통/나쁨)** 노출

#### 신체 치수 측정 방법 (Depth 사용 시)

1. 카메라-사용자 절대 거리 추출 (핵심 키포인트 depth 샘플링 + 중앙값)
2. 핀홀 카메라 모델 역투영으로 픽셀 거리 → 실세계 거리 변환
3. 키포인트 간 거리 기반 7개 신체 치수 산출
4. 둘레 치수는 타원 근사 (정면 영상 한계로 추정치)

#### Focal Length 획득 순서

1. `MediaStreamTrack.getCapabilities()` (지원 시)
2. 기본값 폴백 (스마트폰 전면: ~3.5mm, 노트북: ~3.6mm)
3. 사용자 캘리브레이션 (A4 용지 등 기준 물체)
4. MVP 전략: 기본값 폴백 + 사용자 키 입력 시 스케일 보정

## 9. 데이터 모델 개요

### 9.1 핵심 엔티티

| 엔티티 | 설명 |
|--------|------|
| users | 사용자 (role: user/vendor/manager/admin) |
| brands | 업체/브랜드 |
| garments | 의류 기본 정보 (카테고리, 에셋 상태) |
| garment_images | 상품 이미지 (다각도: front/back/side 등) |
| garment_variants | 의류 변형 (색상, 사이즈, 핏 타입, 실측 치수) |
| body_presets | 바디 프리셋 (성별+사이즈별 VRM 모델) |
| fitting_sessions | 피팅 세션 로그 |
| body_measurements | 신체 측정 결과 (7개 치수, 측정 방식) |
| fit_evaluations | 핏 평가 결과 (핏 타입, 적합도, 항목별 차이) |
| favorites | 의류 즐겨찾기 (users ↔ garments N:M) |
| sdk_configs | SDK 설정 (API 키, 도메인 제한) |
| refresh_tokens | Refresh Token 관리 (회전/폐기) |

### 9.2 엔티티 관계 요약

```
brands ──< garments ──< garment_images
               │
               ├──< garment_variants ──< fit_evaluations
               │
users ──< favorites >── garments

users ──< fitting_sessions >── garment_variants
               │
               ├── body_presets (참조)
               │
               └──< body_measurements ──< fit_evaluations

users ──< refresh_tokens
brands ──< sdk_configs ──< fitting_sessions (선택)
```

## 10. 인터페이스 요구사항

### 10.1 외부 인터페이스

| 인터페이스 | 프로토콜 | 설명 |
|-----------|---------|------|
| 쇼핑몰 연동 | REST (HTTPS) | 의류 카탈로그 동기화(선택), 상품 상세 딥링크/SDK 임베드 |
| CDN | HTTPS | glTF/GLB 에셋 서빙 |
| 카메라 | WebRTC getUserMedia | 브라우저 카메라 접근 |

### 10.2 내부 인터페이스

| 인터페이스 | 프로토콜 | 설명 |
|-----------|---------|------|
| FE → BE | REST (HTTPS) | 카탈로그, 사용자, 세션 CRUD |
| BE → DB | TCP | PostgreSQL 연결 (SQLAlchemy) |
| BE → Redis | TCP | 캐시 조회/저장, Pub/Sub |

### 10.3 에셋 생성 상태 알림

- **MVP**: REST 폴링 (GET /api/v1/garments/{id} → asset_status 필드, 10초 간격)
- **확장**: Server-Sent Events (SSE) 실시간 알림

### 10.4 에러 핸들링 전략

| 상황 | 복구 전략 |
|------|----------|
| 카메라 권한 거부 | 마네킹 뷰 폴백 + 권한 안내 |
| MediaPipe 모델 로드 실패 | CDN 재시도 (최대 3회) → 에러 메시지 |
| 포즈 감지 실패 (사람 없음) | 마지막 유효 포즈 유지, 3초 후 초기 포즈 |
| FPS 급락 (< 15fps) | 모델 다운그레이드 → 해상도 축소 |
| WebGL 컨텍스트 손실 | 씬 재초기화 |

### 11.1 호환성 매트릭스

| 브라우저 | Cloth 모드 | Depth 모델 | 예상 FPS | 비고 |

| **데스크톱 Safari 17.4+** | SkinnedMesh + NormalMap | Depth (WebGL, 저주기) | 40-55fps | WebGL 2.0 기반 |

### 11.2 성능 벤치마크 타겟

| 디바이스 분류 | 예시 | 트래킹 모델 | 타겟 FPS |
|-------------|------|-----------|---------|
| 데스크톱 고사양 | RTX 3060+ | Heavy | 60fps |
| 데스크톱 저사양 | Intel UHD | Full | 45fps |
| 모바일 고사양 | Galaxy S24, iPhone 15 | Full | 45fps |
| 모바일 중사양 | Galaxy A54, iPhone 13 | Lite | 30fps |
| 모바일 저사양 | 3년+ 구형 | Lite + 해상도 축소 | 25fps |

### 11.3 점진적 강등 전략

```
기능 감지 순서:
1단계: WebGL 2.0 + GPU 성능 확인
2단계: GPU 성능 충분 + ONNX Runtime 지원 → Full (SkinnedMesh + NormalMap + Depth 선택)
3단계: 중간 성능 → SkinnedMesh + NormalMap (Depth 비활성화)
4단계: 최소 모드 → SkinnedMesh only (NormalMap + Depth 모두 생략)
```

## 14. 용어 정의

| 용어 | 정의 |
|------|------|
| WebAR | 웹 브라우저 기반 증강현실. 별도 앱 설치 없이 카메라를 통해 가상 객체를 현실에 오버레이 |
| glTF | GL Transmission Format. 3D 씬/모델 전송을 위한 표준 포맷 |
| GLB | glTF의 바이너리 버전. 모든 데이터를 단일 파일로 패킹 |
| Draco | Google의 3D 메쉬 압축 라이브러리 |
| KTX2 | Khronos Texture Container 2. GPU 압축 텍스처 컨테이너 |
| XPBD | Extended Position-Based Dynamics. 실시간 물리 시뮬레이션 알고리즘 |
| VAT | Vertex Animation Texture. 버텍스 애니메이션을 텍스처로 인코딩하는 기법 |
| SDF | Signed Distance Field. 충돌 감지에 사용되는 거리 필드 |
| 1-Euro Filter | 입력 신호의 속도에 따라 컷오프 주파수를 적응적으로 조절하는 저역통과 필터. 저속 시 강한 스무딩(지터 제거), 고속 시 약한 스무딩(지연 최소화). Casiez et al., CHI 2012 |
| SkinnedMesh | 본 리깅이 적용된 3D 메쉬. 본 변환에 따라 변형 |
| VRM | pixiv에서 유지보수하는 3D 아바타 표준 포맷 (glTF 확장). VRMHumanoid 본 구조 표준화 |
| Kalidokit | MediaPipe 키포인트 → 휴머노이드 본 회전값 변환 라이브러리 |
| Depth Anything V2 | 단안 카메라 영상으로부터 depth map을 추정하는 모델. Metric Depth는 절대 스케일(미터)을 목표로 함 |
| Fit Type (핏 타입) | 의류와 신체 간 여유량에 따른 핏 분류. slim(슬림핏), regular(레귤러핏), oversize(오버핏) |
| 적합도 (Suitability) | 신체 치수와 의류 치수 간 핏 적합 정도를 백분율(%)로 표현한 값 |
| 정확도 (Accuracy) | 신체 측정 결과의 신뢰도(표시용)를 백분율(%)로 표현한 값. 상한 99 |
| PBR | Physically Based Rendering. 물리 기반 렌더링 (Albedo + Normal + Roughness + Metallic) |
| TRELLIS.2 | Microsoft의 Image-to-3D 생성 모델 (MIT 라이선스). 풀 PBR 출력 지원 |
| Robust Weight Transfer | SIGGRAPH Asia 2023 논문 기반 자동 리깅 알고리즘. 바디→의류 본 웨이트 전사 |
| LBS | Linear Blend Skinning. 본 가중치 기반 메쉬 변형. Candy-Wrapper 효과 등 고유 한계 존재 |
| R3F | react-three-fiber. React 컴포넌트 모델과 Three.js의 선언적 통합 라이브러리 |
